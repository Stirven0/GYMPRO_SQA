Conclusiones y Recomendaciones

Fortalezas

  • 119 pruebas funcionales PASS (100%) — todos los módulos operativos y funcionales
  • Cobertura completa de 3 roles con 21 rutas documentadas y diferencias de privilegios correctas
  • API REST funcional con 11 endpoints verificados
  • Tiempos de respuesta rápidos: avg 554 ms (JMeter, 150 peticiones)
  • Diseño responsivo funcional en todos los viewports probados
  • Sin vulnerabilidades críticas/altas/medias detectadas por OWASP ZAP
  • Documentación completa: mapas de URL para 3 roles, 43 capturas de evidencia

Debilidades

  • CAPTCHA solo client-side — se autentica sin resolverlo vía API directa (D-001)
  • API sin filtro por rol — fuga de datos entre usuarios (D-004)
  • Cookie de sesión sin flag Secure (D-002)
  • Sin protección anti-CSRF ni autenticación JWT
  • Tolerancia a fallos y recuperabilidad no verificables sin entorno de pruebas controlado
  • Código inline JS sin separación de capas (dificulta mantenibilidad)
  • Capacidad probada solo hasta 10 usuarios concurrentes

Recomendaciones

  1. Implementar validación server-side del captcha (crítico)
  2. Filtrar datos de API por rol para evitar fuga de información
  3. Agregar flag Secure a la cookie de sesión
  4. Implementar autenticación con JWT y protección CSRF
  1. Separar lógica JS en módulos para mejorar testeabilidad y mantenibilidad
  2. Realizar pruebas de carga con mayor concurrencia (>50 usuarios)
  3. Implementar registro de auditoría con trazabilidad por usuario
  4. Establecer pruebas de recuperación y tolerancia a fallos en entorno controlado
